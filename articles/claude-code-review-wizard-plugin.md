## TL;DR

- Claude Code の AskUserQuestion はターミナル UI なので、選択肢を読み比べる質問には向かない。そもそも比較表も図も出せない。
- review-wizard は、その質問をブラウザのウィザード画面（1問ずつ表示、ステッパー付き）で出すプラグイン。質問ごとに比較表やインライン SVG の図（`detail`）を添えられ、これが既定で描画される。回答は JSON で返る。
- 実装は一時的なローカル HTTP サーバ方式で、外部 npm 依存はゼロ。回答を受け取ったら閉じて終了し、常駐しない。
- 導入すると、質問が3問以上、あるいは選択肢の比較検討が要るときは Claude Code が自動でこちらを使い、1〜2問の即答は AskUserQuestion のままになる（SKILL.md の基準による）。
- リポジトリ: <https://github.com/uehaj/review-wizard>

## はじめに

NTTテクノクロスの上原です。

Claude Code には AskUserQuestion という仕組みがあります。作業の分岐点で選択肢を出し、ターミナルの中でそのまま答えられる。1〜2問ならこれで何の不満もありません。手を止めずに答えて、すぐ作業に戻れます。

ところが、質問が3問4問と続き、選択肢ごとに数行の説明が付きはじめると、様子が変わります。2問目を読んでいるうちに1問目の説明は画面の上へ流れていき、選択肢どうしを見比べようとすれば、スクロールで上下を往復することになる。読み直せないわけではありません。ただ、3問目に答えるころには、1問目で自分が何を選んだのかも怪しくなっています。

質問を短くしてもらえば済む話だろうか、とも考えました。しかし説明を削れば、判断の材料も一緒に消えます。それに、方式を選ぶような質問で本当にほしいのは、削れる説明ではなく、性質を並べた比較表や、処理の流れを示した図です。縦一列にテキストが流れていくターミナルには、その表も図も置けません。答えづらさの正体は質問の量ではなく、判断の材料を並べて見せる場所がないことでした。

であれば、表も図も置けるブラウザに、見比べたい質問だけを出せばいい。そう考えて作ったのが review-wizard というプラグインです。まずは動いている画面を見てください。

## 質問に表と図を出す（detail）

さきほどの2画面で選択肢の上にあった比較表とワイヤーフレームが、ブラウザに出す一番の狙いです。一行の補足説明で選べる質問ばかりではありません。画面例2のセッション管理方式などは、方式ごとの性質を表で見比べ、トークンの流れを図で確かめて、はじめて選べる類の質問です。そこで各質問に `detail` という項目を持たせました。`detail` は質問文の下にそのまま描画され、次のものが使えます。

- 表：`<table>`
- 図：インライン `<svg>`（テキストなので外部依存もオフライン制約もそのまま）
- 画像やスクショ：`<img src="data:image/png;base64,...">`（データ URI で埋め込み、外部 URL は使わない）

質問1件のデータはこう書きます（Claude Code からの渡し方は後述します）。

```json
{
  "question": "セッション管理方式はどれにしますか？",
  "header": "認証方式",
  "detail": "<table>…</table><svg>…</svg>",
  "options": [{ "label": "サーバセッション" }, { "label": "JWT" }]
}
```

画面例1のチャットアプリの3案も、ワイヤーフレームは `detail` に入れた SVG、比較表は `<table>` です。

`detail` は、作者（利用者自身か、指示を受けたエージェント）が書いた信頼済みの HTML として、エスケープせずそのまま描画します。これが既定の挙動です。そのぶん、画面は 127.0.0.1 でワンタイムトークン付きの URL にだけ返し、自分だけが見るローカル用途に限る、という前提で割り切っています。プレーン表示に戻したいときは `--no-rich` を付けると、サーバが `detail` をクライアントへ渡す前に取り除くので、HTML の注入自体が起きません。

## 裏のしくみ

ブラウザに画面を出すといっても、フレームワークもビルドも使っていません。中身は `scripts/review_wizard.ts` という単一ファイルの CLI で、しくみは3点だけです。

まず、起動すると 127.0.0.1 に一時的な HTTP サーバを立てます。URL には毎回ランダムなワンタイムトークンを埋め込み、そのパスでだけウィザード画面を返します。ブラウザが URL を開き、回答が送信されると、サーバは回答を JSON で書き出してそのまま閉じます。起動して、答えを待って、閉じる。ポーリングも常駐もない短命なプロセスです。

次に、外部 npm 依存がありません。使うのは Node 標準モジュールだけで、画面の HTML と CSS と JavaScript もすべてスクリプト内にインラインで持っています。外部リソースへの参照が一切ないので、オフラインでも動きます。

最後に、`review_wizard.ts` を `.ts` のまま `node` で直接実行します。Node の Type Stripping（型注釈をコンパイルなしで取り除く機能）を使うためで、Node 23.6 以降が前提です。実行時に `ExperimentalWarning` が出ますが、Type Stripping が実験的機能である旨の通知で、動作には影響しません。

では、答え忘れた項目があったらどうなるのでしょうか。選択肢か「その他」のどちらかが埋まらないかぎり「次へ」は押せません。受け取るサーバ側でも同じ条件を検証し、満たさなければ 400 を返します。画面とサーバの二重チェックで、不完全な回答が JSON に書き出されることを防いでいます。

質問 JSON と回答 JSON の形式は、外部利用者との互換性契約として今後も変えない方針です（任意項目を足すことはあっても、既存の形式は壊しません）。項目の詳細は README にあります。

## 導入と使い方

マーケットプレイス経由なら次の2行です。

```bash
claude plugin marketplace add https://github.com/uehaj/review-wizard.git
claude plugin install review-wizard@review-wizard-marketplace
```

開発中や導入前の確認では、ローカルのディレクトリを直接読み込ませます。

```bash
claude --plugin-dir /path/to/review-wizard
```

Claude Code から使うときは、質問 JSON を一時ファイルに書き、バックグラウンドで実行します。回答が送信されるまでプロセスは終わらないので、フォアグラウンドで待つと Claude Code 自体が止まってしまいます。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/review_wizard.ts" \
  --questions <in.json> --out <out.json> --timeout 1800
```

起動すると標準出力に `review_wizard: <URL>` が出て、その URL が自動で開きます。プロセスが終わったら、終了コードで結果を判別し、`--out` の回答 JSON を読みます。終了コードは、回答受領が 0、入力エラーが 1、タイムアウトやサーバ起動失敗が 2、中断が 130 です。

### 使いどころ

この使い分けを、利用者が質問のたびに指示する必要はありません。プラグインの SKILL.md に「質問が3問以上、あるいは選択肢の比較検討が要るときに AskUserQuestion の代わりに使う。1〜2問の即答は AskUserQuestion のまま」という基準が書いてあり、Claude Code はスキルの説明文を読んで起動を判断します。つまり導入しておけば、場面に応じて自動的に使い分けられます。基準を変えたいときは、CLAUDE.md に自分のルールを書いて上書きできます。

なお、編集やコマンド実行を自動承認するモードで長時間走らせる使い方だと、そもそも途中で質問される機会自体が減ります。review-wizard が効くのは、判断を質問で拾いながら進める対話的な使い方をしているときです。

## まとめ

スクロールを上下しながら選択肢を見比べていた冒頭の場面は、比較表も図もついた1画面に収まるようになりました。仕掛けは一時ローカルサーバと外部依存ゼロの単一スクリプトで、質問と回答を JSON でやり取りするだけです。

一方で、1〜2問の即答なら、手を止めずに答えられる AskUserQuestion のほうが速いままです。どの質問からを review-wizard に任せるかは SKILL.md の基準にしたがって Claude Code が自動で判断するので、導入後に利用者がすることはありません。ふだんの作業で答えづらさを感じる線が基準と合わなければ、CLAUDE.md で自分の線に調整してください。
